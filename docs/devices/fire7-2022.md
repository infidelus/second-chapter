# Amazon Fire 7 (2022, 12th generation)

How to install: [fire7-install-guide.md](../fire7-install-guide.md). These
are the background notes.

| | |
|---|---|
| Codename | `quartz` |
| Released | June 2022 |
| Processor | MediaTek MT8168, 64-bit ARM (`arm64-v8a`) |
| Memory | 2 GB |
| Storage | 16 GB |
| Screen | 7 inches |
| Original software | Fire OS 8 (Android 11), with ads. Tested on build RS8338 |
| Kernel | Linux 4.14 (Amazon's) |
| Second Chapter approach | LineageOS 20 (Android 13) as a generic system image (GSI), then KOReader |

There's no Linux (Nura/postmarketOS) port for this tablet, so the Nexus 7
approach isn't available. A plain Android GSI is the way to replace Fire OS.

## Results (November 2026)

LineageOS 20 runs well: noticeably quicker than Fire OS, which runs mostly
32-bit apps. Wi-Fi, touch, brightness, sleep and wake all work.

| Measurement | Result |
|---|---|
| Mostly asleep | 100% → 94% over about 38 hours, with a little use: about **0.16% an hour**, roughly three weeks on a charge |
| Reading in KOReader, brightness 53% | 94% → 92% in 33 minutes: about **3.6% an hour** (whole-percent readings, so 2–5%) |

Android's "Battery usage" screen shows no data on this GSI.

## Partitions

`super` (3.87 GB) holds two logical partitions, **system** (3.39 GB) and
**vendor** (300 MB). There are no `_a`/`_b` slots. Other partitions include
`boot`, `vbmeta`, `recovery`, `lk`/`lk_real`, `tee1`/`tee2` (and `_real`),
`nvcfg` and `userdata`. In the unlock's TWRP, `mmcblk0boot0` (the preloader)
is linked to `/dev/null` on purpose.

## Findings

- **Android 14 doesn't start.** LineageOS 21 restarts into recovery at the
  SELinux stage. Android 14 doesn't support 4.14 kernels; the unlock's
  developer reports running Android 14 and later with unpublished "minor
  adjustments to the stock kernel". Android 13 (LineageOS 20) works on the
  stock kernel.
- **Amazon's SELinux version naming.** The vendor part declares its policy
  version as `30.0.0` (in `/vendor/etc/selinux/plat_sepolicy_vers.txt`), and
  names every versioned type with `_30_0_0` (in `plat_pub_versioned.cil` and
  `vendor_sepolicy.cil`; about 14,500 occurrences). Android expects `30.0`
  and `_30_0`, so init looked for a missing `mapping/30.0.0.cil`, and then
  couldn't resolve the types in `mapping/30.0.cil`. Renaming both fixes it.
  One `genfscon` rule then clashes with Android 13's
  (`/sys/kernel/sched_util_clamp_min_rt_default`, labelled
  `proc_sched_util_clamp_min_rt_default` by Amazon and `proc_sched` by
  Android); removing Amazon's line lets the policy compile. The result was
  checked by compiling the whole policy on a PC with `secilc`, the same way
  init does (`-m -M true -G -N -c 31`, kernel policy version 31).
- **Lost start-up messages.** Android's start-up messages were dropped by
  the kernel's rate limit for `/dev/kmsg`, hiding the real error. Adding
  `printk.devkmsg=on` to the boot image's command line showed them; see
  [`fire7/tools/bootimg-cmdline.py`](../../fire7/tools/bootimg-cmdline.py).
  The kernel log of a failed start is kept in
  `/sys/fs/pstore/console-ramoops`.
- **Verified boot.** `vbmeta`'s flags were already `02` (verification
  disabled) after the unlock; Second Chapter sets `03`.
- **Writing the system image.** The GSI (with `shared_blocks`, so read-only)
  is written with `dd` into `/dev/block/mapper/system`. TWRP's "Install
  Image" only offers the whole of `super`. After Format Data, `/sdcard` isn't
  on storage, so copies must go to `/data`; streaming with `adb exec-in`
  corrupted the image.
- **Kindle books:** the official web reader works in the browser, so no
  Kindle app is needed.
